# Конфигурация и ZIP

Русский | [English](en/CONFIGURATION.md)

Путь: `plugins/ServerBootstrap/config.yml`. Схема: `config-version: 1`. Версия схемы и версия плагина различаются. Изменения читаются при следующем запуске; команды reload нет. При некорректной конфигурации установка и вход игроков блокируются; status сообщает причину без значения секрета. Дубликаты YAML-ключей, неизвестные поля и неверные типы запрещены.

## Поля верхнего уровня

| Поле | Значение по умолчанию | Назначение |
|---|---|---|
| config-version | обязательно для новой схемы | Целое число 1 |
| profiles | обязательно, можно {} | Имена → описания профилей |
| limits.max-download-bytes | 268435456 | Максимум ZIP, включая поток без Content-Length |
| limits.max-extracted-bytes | 1073741824 | Сумма распакованных байтов, включая неустанавливаемые файлы |
| limits.max-entries | 10000 | Число записей ZIP, включая каталоги; максимум 1000000 |
| limits.connect-timeout-seconds | 15 | Таймаут соединения; 1–3600 |
| limits.download-timeout-seconds | 180 | Общий срок загрузки, включая тело и все редиректы; 1–86400 |
| listener.enabled | false | Включить HTTP |
| listener.bind | 127.0.0.1 | Только 127.0.0.1, ::1 или 0.0.0.0 |
| listener.port | 8080 | 1–65535; 0 в production-конфигурации запрещён |
| listener.token | пусто | Секрет HTTP: минимум 32 символа при включённом listener |
| listener.token-env | пусто | Имя переменной окружения вместо token |

Размеры — положительные целые числа в байтах. Значения YAML boolean должны быть true/false без кавычек. Все версии указывайте строками в кавычках.

## Профиль

Имя: 1–64 символа, первая буква/цифра, далее буквы ASCII, цифры, `_`, `-`. Имя — ключ в `profiles`. Значение `none` зарезервировано для непривязанного узла.

| Поле профиля | По умолчанию | Назначение |
|---|---|---|
| source.type | обязательно | github, gitlab, https, google-drive |
| source.mode | repository для GitHub/GitLab, direct для остальных | GitHub/GitLab: repository или release; остальные: direct |
| source.url | обязательно | HTTPS-адрес репозитория либо ZIP-артефакта |
| source.api-base | определяется источником | База GitHub/GitLab API для repository; без query |
| source.ref | обязательно для repository | Ветка, тег или commit; рекомендуем неизменяемый commit |
| source.auth.token | пусто | Токен, хранимый в конфигурации |
| source.auth.token-env | пусто | Переменная окружения с токеном |
| source.auth.header | PRIVATE-TOKEN для gitlab, иначе Authorization | Разрешены Authorization, PRIVATE-TOKEN, JOB-TOKEN |
| source.auth.scheme | Bearer для Authorization, иначе пусто | Bearer, token или пустая строка |
| version | обязательно | Строковая метка сборки; 1–128 символов ASCII, первый — буква/цифра, далее также . _ / + - |
| sha256 | пусто | 64 hex-символа; регистр неважен |
| archive-root | auto | auto, точка "." или относительный каталог внутри ZIP |
| apply.include | [plugins] | Непустой список относительных путей файлов/каталогов |
| apply.required-files | [] | Конкретные файлы, которые обязаны попасть в список установки |
| apply.mode | direct | direct — замена выбранных файлов; maintenance — полная замена миров через служебный мир |
| apply.worlds | [] | Только maintenance: 1–1000 уникальных имён миров; список должен совпадать с include |
| restart | true | direct: запросить restart; maintenance: остановить сервер после подготовки и замены, запуск обеспечивает хостинг/администратор |

`version` — метка администратора; совпадение с содержимым обеспечивает SHA-256, а не название. Если sha256 не задан, проверяются размер, структура и CRC ZIP, но подлинность артефакта не установлена; журнал пишет `checksum=not-configured`.

Пара `token` и `token-env` взаимоисключающая. Переменная должна существовать в окружении процесса сервера. Строки вида `${token}` не подставляются и отклоняются. Перезапустите процесс после изменения окружения.

`include` — буквальные пути, не glob-шаблоны. Путь каталога включает всё его поддерево. В direct существующие файлы, которых нет в архиве, сохраняются. В maintenance каждый перечисленный мир полностью заменяется снимком: прежние чанки и данные перемещаются в backup. Обязательные файлы должны находиться внутри include и вне защищённых путей.

Имена миров для maintenance: 1–64 ASCII буквы/цифры/`_`/`-`, первый символ — буква/цифра; системные каталоги, Windows device names и префикс `sb_maintenance_` запрещены. Каждый мир должен содержать `level.dat`. Режим устанавливает только миры, без plugins/config/server.properties. Подробности: [MAINTENANCE.md](MAINTENANCE.md).

## Структура архива

```text
plugins/
  ExamplePlugin.jar
  ExamplePlugin/
    config.yml
config/
  paper-global.yml
server.properties
world/
  level.dat
  region/
    r.0.0.mca
```

Включайте только нужные пути, например `[plugins, config, server.properties, world]`. Этот смешанный список допустим только для direct с offline-установкой миров. На хостинге используйте maintenance с отдельным списком миров. Версия формата мира должна соответствовать ядру сервера; ServerBootstrap не конвертирует миры и не делает downgrade.

`archive-root: auto` принимает содержимое в корне ZIP либо один внешний каталог, добавленный GitHub/GitLab. Если нужная структура глубже, задайте её явно, например `archive-root: deployment/server`. Поиск произвольного каталога `plugins` по всему архиву не выполняется.

Должен быть хотя бы один устанавливаемый файл. Пустые каталоги сами по себе не создаются. README и прочие файлы вне include распаковываются для проверки, но не копируются в сервер.

## Защита путей

Запрещены абсолютные пути, `..`, `.`, обратные слеши, UNC/drive-пути, NTFS alternate streams, управляющие символы, Windows device names, окончания пробелом/точкой, дубли и неоднозначный регистр/Unicode. Глубина пути ограничена 32 компонентами, длина — 1024 символами. Ссылки и junction в пути назначения отвергаются.

UNIX-атрибуты ZIP не воспроизводятся: символические ссылки из архива не создаются, их содержимое трактуется как обычный файл. Исполняемые биты ZIP не переносятся. Профили предназначены для JAR, конфигураций и данных.

Пропускаются `plugins/ServerBootstrap/**`, `plugins/NodeMetrics/**`, JAR с соответствующими префиксами в `plugins/`, `.git/**`. Фактический путь работающего ServerBootstrap JAR дополнительно защищён даже при переименовании. Конфигурация, журнал и состояние плагина не могут быть заменены архивом.

## Секреты

Ограничьте доступ к config.yml, переменным окружения и каталогу резервных копий пользователем серверного процесса. Не коммитьте настоящие токены в Git. Подписанные URL могут содержать секреты — URL и query не выводятся в логи. Тела HTTP-ошибок и исходные исключения сетевых библиотек также не журналируются.
