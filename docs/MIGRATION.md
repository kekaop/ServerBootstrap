# Миграция с 1.0-SNAPSHOT

Русский | [English](en/MIGRATION.md)

1. Остановите сервер, сохраните его резервную копию и старый config.yml.
2. Удалите старый JAR ServerBootstrap и поместите новый в plugins. Не оставляйте два JAR одного плагина.
3. Конфигурация без config-version распознаётся как legacy. GitHub owner/repo-template и GitLab project-path-template продолжают работать, %s заменяется именем профиля. Уберите неразрешённые placeholders токенов, оставив пустую строку для публичного репозитория.
4. При первом чтении legacy-конфигурации существующий node-profile сохраняется в installed.properties как привязка с version=unknown. Старое first-install больше не используется и не сбрасывается. Если старая установка когда-либо завершилась ошибкой, проверьте корректность старой привязки вручную: исходная версия записывала её слишком рано.
5. Перенесите описание профиля в схему 1 по examples/config.yml. Укажите конкретный ref, метку версии и SHA-256. Не удаляйте installed.properties при смене формата: в нём сохраняется привязка.
6. Перезапустите сервер, выполните check, затем update.

Если хотите сразу заменить legacy config.yml, сначала импортируйте старую привязку запуском новой offline-утилиты с командой check на старом конфиге либо перенесите известную привязку в installed.properties вручную при остановленном сервере. Не выдавайте неизвестную старую версию за проверенную.

## Изменения поведения

- setup-server <profile> теперь также обновляет уже привязанный профиль. Другой профиль отвергается.
- При legacy-конфигурации HTTP всегда отключён. Это сознательная миграция безопасности: прежние secret и port не переносятся автоматически.
- Новый HTTP принимает только POST /update, пустое тело и Authorization: Bearer. Успешное принятие — HTTP 202; GET /status показывает результат. Старый JSON с secret нужно заменить.
- Корень установки — рабочий каталог сервера, а не world-container. Миры за пределами этого каталога не изменяются.
- Архив имеет корень профиля или один wrapper; эвристический поиск plugins на глубине трёх каталогов удалён. Для старого нестандартного ZIP задайте archive-root явно.
- В direct отсутствующие в архиве файлы сохраняются. Явный maintenance заменяет перечисленные каталоги миров целиком, сохраняя прежнее содержимое в backup.
- Миры, загруженные ядром, не заменяются во время работы. Для хостинга выберите apply.mode: maintenance с явно перечисленными мирами (MAINTENANCE.md), либо используйте offline-утилиту с direct. Незавершённые direct-транзакции восстанавливаются только offline.
- NodeMetrics JAR и каталог остаются защищены. Неявная запись nodeName после установки удалена: задайте nodeName самостоятельно в plugins/NodeMetrics/config.yml при остановленном сервере. Это устраняет изменение стороннего плагина вне транзакции.
- Отдельное permission serverbootstrap.admin выдаётся явно; OP сам по себе его не получает.
- Конфигурации вне plugins доступны через apply.include.
- Автоматические резервные копии и staging сохраняются; администратор управляет их сроком хранения.

Физическое переключение профиля возможно только как ручная переподготовка узла: остановить сервер, сделать полную копию, проверить совместимость содержимого, убрать старые данные по своему плану и состояние привязки. Команды переключения и автоматической очистки нет.
