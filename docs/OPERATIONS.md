# Эксплуатация

Русский | [English](en/OPERATIONS.md)

## Команды и разрешения

| Команда | Действие |
|---|---|
| /setup-server <profile> | Совместимая установка или обновление этого профиля |
| /serverbootstrap install <profile> | Установка или обновление |
| /serverbootstrap update [profile] | Обновление; без аргумента берёт привязанный профиль |
| /serverbootstrap check <profile> | Проверить источник, SHA, ZIP, структуру и целевые пути без установки |
| /serverbootstrap current | Профиль, версия, фактическая SHA-256, дата установки |
| /serverbootstrap status | Последняя/текущая операция, ID, фаза, результат |
| /serverbootstrap help | Справка |
| /serverbootstrap maintenance-status | Сохранённое состояние замены миров, включая ошибку запуска |
| /serverbootstrap maintenance-retry | Повторить переключение/восстановление при следующем запуске |
| /serverbootstrap maintenance-cancel | Отменить ещё не закоммиченную замену, при необходимости через откат |

Alias: /sb. Все команды доступны консоли. Другому отправителю требуется `serverbootstrap.admin`; default=false, автоматического доступа у OP нет. Permission разрешает и установку, и обусловленный профилем перезапуск, поэтому выдавайте его только доверенным администраторам.

Команда немедленно сообщает ID операции, окончательный результат отправляется позже. Загружать ZIP и распаковывать его в основном серверном потоке плагин не будет. Одновременно на узле разрешена только одна операция, включая check. Повторный запрос отвергается, а не ставится в бесконечную очередь.

## Обновление работающего сервера

До установки выведите узел из балансировщика, запретите соединения на уровне инфраструктуры, дождитесь выхода игроков и остановите посторонние записи. Если игроки онлайн, применение запрещено. Плагин блокирует новые логины на время применения и ожидания перезапуска.

Загруженные миры нельзя заменять в direct. Для хостинга без внешних программ предусмотрен [maintenance-режим с двумя перезапусками](MAINTENANCE.md). JAR обновлённого плагина загружается только после перезапуска. Файлы конфигураций активных плагинов могут быть перезаписаны этими плагинами при выключении: для таких конфигураций используйте offline-режим.

В direct `restart: true` вызывает стандартный `Server.Spigot.restart()`. Настройте restart-script в spigot.yml и/или внешний менеджер процессов. Некоторые окружения останавливают сервер, но не поднимают его снова; настройка запуска относится к администратору. После успешного commit при restart=true новые операции блокируются до перезапуска. Если автоматический restart не сработал, выполните его вручную. При restart=false плагин фиксирует файлы без hot-reload.

Maintenance вызывает только остановку сервера через Bukkit API, без запуска restart-script. На служебном запуске HTTP listener отключён, команды maintenance доступны независимо от config.yml.

## Offline-утилита

Распакуйте `ServerBootstrap-2.1.0-offline.zip` **в отдельный каталог**, не в plugins. В lib лежат плагин и зависимости общего парсера конфигурации. Offline-режим не запускает Minecraft и не требует принятия его EULA.

Сначала остановите целевой сервер. В его каталоге должен быть `plugins/ServerBootstrap/config.yml`.

```sh
sh offline.sh /srv/minecraft lobby check --server-stopped
sh offline.sh /srv/minecraft lobby install --server-stopped
```

Windows:

```powershell
.\offline.cmd "D:\Minecraft\lobby" lobby check --server-stopped
.\offline.cmd "D:\Minecraft\lobby" lobby install --server-stopped
```

Offline install использует apply.mode: direct; maintenance-профили применяются серверным плагином. Пока есть незавершённая maintenance-операция, offline-команды запрещены — сначала завершите или отмените её через плагин.

Работает на Java 17/21/25. Используется та же цепочка загрузки, проверки, транзакции и состояния. `restart` в offline-режиме означает, что после завершения сервер нужно запустить вручную. Код завершения: 0 — успех, 1 — ошибка, 2 — неправильные аргументы.

Утилита захватывает node.lock и session.lock найденных миров внутри корня (кроме plugins). node.lock уже занят, пока плагин загружен на сервере. Флаг --server-stopped — подтверждение состояния оператором: не отключайте плагин ради обхода блокировки работающего сервера, не запускайте другой сервер в том же каталоге. Внешние world-container и символьные ссылки не поддерживаются.

## HTTP API

В конфигурации:

```yaml
listener:
  enabled: true
  bind: "127.0.0.1"
  port: 8080
  token-env: SERVERBOOTSTRAP_HTTP_TOKEN
```

Секрет: случайное значение длиной хотя бы 32 символа, заданное окружению процесса. Listener принимает пустое тело; секрет только в заголовке. Не используйте query-параметры.

```sh
curl --request POST --header "Authorization: Bearer $SERVERBOOTSTRAP_HTTP_TOKEN" http://127.0.0.1:8080/update
curl --header "Authorization: Bearer $SERVERBOOTSTRAP_HTTP_TOKEN" http://127.0.0.1:8080/status
```

| Ответ | Значение |
|---|---|
| 202 + accepted, operation | Запрос принят; установка ещё не завершена |
| 200 на GET /status | ID, профиль, фаза и сообщение последней операции |
| 400 | Query в URL запрещён |
| 401 | Нет корректного Bearer-секрета |
| 404 | Неправильный путь |
| 405 + Allow | Неправильный метод |
| 409 | Узел не привязан, операция уже выполняется, ожидается restart/восстановление или профиль недоступен |
| 413 | Передано тело запроса или Transfer-Encoding |

Пример ответа: `{"status":"accepted","operation":"UUID"}`. Фазы direct: QUEUED, DOWNLOADING, VERIFYING, APPLYING, CHECKED, SUCCEEDED, FAILED, RESTART_REQUIRED. Подготовка maintenance может вернуть WAITING_FOR_MAINTENANCE; последующие сохранённые фазы и команды восстановления описаны в [MAINTENANCE.md](MAINTENANCE.md). GET /status после обычного перезапуска начинается с IDLE; установленная версия сохранена в installed.properties. История доступна в серверном журнале и каталоге transactions.

Listener — обычный HTTP на loopback, без собственного TLS. Для внешнего доступа используйте HTTPS reverse proxy, firewall/allowlist CI, ограничение частоты запросов и таймауты клиента на proxy. Включение bind=0.0.0.0 открывает порт на всех IPv4-интерфейсах; не передавайте секрет через открытую сеть без TLS. Не публикуйте этот порт напрямую. Настройте скрытие Authorization в логах proxy. HTTP не обязателен для команд и offline-установки.

## Транзакции и резервные копии

Каталог: `plugins/ServerBootstrap/transactions/<operation-id>/`.

| Файл/каталог | Назначение |
|---|---|
| artifact.zip | Загруженный артефакт |
| staging/ | Проверенное распакованное содержимое |
| preview.properties | Список выбранных файлов, источник, версия, размер, SHA |
| backup/0, backup/1, … | Оригиналы файлов; номера сопоставлены в plan.properties |
| plan.properties | Полный список, наличие прежнего файла, SHA резервной копии, новые каталоги |
| phase.properties | PREPARED / APPLYING / COMMITTED / ROLLED_BACK / ROLLBACK_FAILED и число записанных намерений |
| rollback.properties | failed-count и конкретные пути, которые не удалось восстановить |
| installed.properties | Подготовленное новое состояние узла |

Порядок: загрузка → SHA → полная распаковка/CRC → структура/пути → preview → проверки обслуживания → резервные копии → журнал → замены → состояние узла → COMMITTED → restart.

До применения затрагивается только служебная область. Каждая замена использует временный файл рядом с целью, fsync и atomic rename. Файловые системы без atomic move отвергаются с откатом. Весь каталог сервера не переключается одним действием. Долговечность при отключении питания зависит также от файловой системы и оборудования; это не замена полному внешнему backup.

При ошибке во время применения оригиналы восстанавливаются, созданные файлы убираются, созданные пустые каталоги удаляются. Посторонние файлы в новых каталогах сохраняются. Если восстановить что-то не удалось, операция становится FAILED, новые операции блокируются; в сообщении указано, где найти backup и rollback.properties.

Незавершённая direct-транзакция блокирует установку и вход игроков при следующем запуске. Обычный onLoad уже слишком поздний для безусловной замены главного мира: его метаданные прочитаны ядром. Остановите сервер и восстановите direct-транзакцию offline:

```sh
sh offline.sh /srv/minecraft ignored recover --server-stopped
```

В maintenance восстановление проводится только на подтверждённом запуске со служебным миром; используются команды maintenance-retry/maintenance-cancel, см. MAINTENANCE.md.

Для direct recover не загружает профиль, не требует рабочей сетевой конфигурации и повторяем. Не удаляйте незавершённый журнал и резервные копии. При ROLLBACK_FAILED остановите сервер, проверьте места из rollback.properties, исправьте доступ/блокировки, затем повторите recover. Если backup повреждён, восстановите его из вашей внешней копии и разберите ситуацию вручную; подделывать COMMITTED нельзя.

Служебные данные сохраняются для диагностики. После подтверждённой успешной работы можно вручную архивировать/удалить **целый** каталог завершённой операции с COMMITTED или ROLLED_BACK. Данные check/ошибки до применения не имеют phase.properties; их также можно убрать, когда операция закончилась. Не чистите их во время работы. Плагин не удаляет журналы и backup автоматически.

## Журнал и диагностика

Формат строки:

```text
event=installation operation=UUID profile=lobby version=v1 source=github phase=VERIFYING message=bytes=12345 sha256=... checksum=passed
```

UUID связывает строку с transactions. Для HTTP: event=http-unauthorized/http-rejected/http-update-accepted; для восстановления: event=recovered. URL, query, HTTP-тела и значения токенов не журналируются. Файлы резервных копий могут содержать прежние конфигурации с секретами и требуют защиты.

| Ошибка | Что проверить |
|---|---|
| Invalid field | Имя профиля и поле в сообщении, тип YAML, config-version |
| HTTP 401/403 | Токен, заголовок, права, API-лимиты; cross-origin redirect не получает токен |
| HTTP 404 | URL/ref/asset ID и видимость репозитория |
| Download timed out | Доступ к HTTPS, DNS, proxy, лимиты времени |
| SHA-256 mismatch | Полученный артефакт не совпадает с ожидаемым; не отключайте проверку без выяснения причины |
| ZIP corrupt / no installable files | HTML вместо ZIP, повреждение, archive-root, include |
| Required file missing | apply.required-files и содержимое именно этой версии |
| Unsafe path / junction | Содержимое ZIP или ссылки в целевой структуре |
| Apply failed; rolled back | Свободное место, права, заблокированные JAR на Windows |
| Rollback incomplete | Остановить сервер, изучить rollback.properties и сохранённые backup |
| Node is bound | Нельзя менять профиль обычной командой |
| Loaded world / players online | Вывести игроков; для миров выбрать maintenance либо offline |
| Нет автоматического restart | Проверить spigot.yml и менеджер процессов; файлы уже могли быть закоммичены |
